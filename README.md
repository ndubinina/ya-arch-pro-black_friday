|---------------------|----------|--------------|--------------------------------------|

## Задание 10. Миграция на Cassandra: модель данных, стратегии репликации и шардирования

| Данные   | Критичность                              |
|----------|------------------------------------------|
| Orders   | Критично создание заказа                 |
| Products | Критично быстрое обновление остатков     |
| Carts    | Частое редактирование из primary реплики |

В Cassandra предлагаю вынести:
- orders_in_process - критично быстрое создание заказа, хорошо подходит для геораспределения, быстрый доступ важен к свежим записям, история не так критична и не меняется - ее храним вне cassandra
- cart_items - частые изменения, необходимо минимальное оставание в данных между нодами
- product_rests - остатки продуктов, критичность при обновления, подходит для геораспределения

### Таблица orders_in_process:
| Поле         | Тип       | Обязательное | Описание                          |
|--------------|-----------|--------------|-----------------------------------|
| `id`         | String    | ✓            | Уникальный идентификатор заказа   |
| `user_id`    | String    | ✓            | Идентификатор клиента             |
| `created_at` | Timestamp | ✓            | Дату и время оформления заказа    |
| `status`     | string    | ✓            | Статус корзины - `new`, `paid`    |
| `location`   | string    | ✓            | Геозона заказа                    |

### Ключи orders_in_process:
partition key - user_id - равномерное распределение и относительно небольшой объем для ребалансировки при добавлении ноды
clustering key - created_at

### Стратегии восстановления orders_in_process:
- Hinted Handoff позволяет сделать быстрое восстановление
- Anti-Entropy Repair для восстановления после длительных сбоев

### Таблица product_rests:
| Поле         | Тип     | Обязательное | Описание                        |
|--------------|---------|--------------|---------------------------------|
| `product_id` | String  | ✓            | Уникальный идентификатор товара |
| `location`   | String  | ✓            | Геозона                         |
| `count`      | number  | ✓            | Количество товаров              |

### Ключи product_rests:
partition key - product_id, location - равномерное распределение и отновительно небольшой объем для ребалансировки при добавлении ноды

### Стратегии восстановления product_rests:
- Read Repair - частая операция чтения, позволит оперативно выявить и устранить расхождения
- Anti-Entropy Repair для восстановления после длительных сбоев

### Таблица cart_items:
| Поле          | Тип    | Обязательное | Описание                                          |
|---------------|--------| ------------ |---------------------------------------------------|
| `card_id`     | string | ✓            | Уникальный идентификатор корзины                  |
| `product_id`  | string | ✓            | ID товара                                         |
| `quantity`    | number | ✓            | Количество                                        |
| `expires_at`  | date   | ✓            | Время удаления (для удаления по TTL)              |


### Ключи cart_items:
partition key - card_id - дает равномерное распределение, относительно небольшой объем при ребалансировке

### Стратегии восстановления cart_items:
-  Hinted Handoff - частая операция записи, позволит оперативно выявить и устранить расхождения
- Anti-Entropy Repair для восстановления после длительных сбоев
