| Поле                | Тип      | Обязательное | Описание                             |

| `_id`               | ObjectId | ✓            | Уникальный идентификатор товара      |
| `name`              | string   | ✓            | Наименование товара                  |
| `category`          | string   | ✓            | Категория товара                     |

db.products.createIndex({ category: 1, price: 1 })

Шардирование range-based для ключа: category и и key-based для ключа: id. Такое шардирование поможет равномерно распределить данные

## Задание 8. Выявление и устранение «горячих» шардов

### Набор метрик
- число chunk на шарде
- число чтений/записи на диск на шарде
- время отклика при чтении/записи на шарде
- число connection на шарде

### Стратегия балансировка для горячих шардов
Под hot shard создаем отдельную зону, помещаем в нее несколько шардов и привязываем shard key горячих chunk к этой зоне.

### Механизм автоматического перераспределения данных
Настроить balancer на mongod, который будет перебрасывать chunk на менее загруженный шард.

## Задание 10. Миграция на Cassandra: модель данных, стратегии репликации и шардирования

| Данные   | Критичность                              |
|----------|------------------------------------------|
| Orders, Products   | Критична транзакционная целостность при создании заказа и уменьшении остатков |
| Products    | Частое чтение по фильтру |
| Carts    | Частое редактирование из primary реплики |

В Cassandra предлагаю вынести:
- cart_items - частые изменения, необходимо минимальное отставание в данных между нодами
- products_for_sale_by_category_price - описание доступных продуктов с возможностью фильтрации по категории и цене


### Таблица cart_items:
| Поле          | Тип    | Обязательное | Описание                                          |
|---------------|--------| ------------ |---------------------------------------------------|
| `card_id`     | string | ✓            | Уникальный идентификатор корзины                  |
| `product_id`  | string | ✓            | ID товара                                         |
| `quantity`    | number | ✓            | Количество                                        |
| `expires_at`  | date   | ✓            | Время удаления (для удаления по TTL)              |


### Ключи cart_items:
partition key - card_id - дает равномерное распределение, относительно небольшой объем при ребалансировке

### Стратегии восстановления cart_items:
- Hinted Handoff - частая операция записи, позволит оперативно выявить и устранить расхождения
- Anti-Entropy Repair - для восстановления после длительных сбоев

### Таблица products_for_sale_by_category_price

| Поле        | Тип              | Обязательное | Описание |
|-------------|------------------|--------------|---------|
| `category`  | string           | ✓ | Категория товара |
| `price_level` | enum            | ✓ | Диапазон цены (1 — от 1 руб до 100 руб, 2 — от 101 руб до 200 руб и т.д.) |
| `price`     | number          | ✓ | Цена |
| `product_id`| string           | ✓ | Уникальный идентификатор товара |
| `name`      | string           | ✓ | Наименование товара |
| `attributes`| map<text,text>   |   | Дополнительные атрибуты (цвет, размер и т.д.) |

### Ключи products_for_sale_by_category_price

partition key - (category, price_level) — позволяет равномерно распределить данные и избежать больших партиций внутри популярных категорий.

clustering key - (price, product_id) — обеспечивает сортировку продуктов по цене внутри категории и ценового диапазона и поддерживает уникальность записи по product_id.

### Стратегии восстановления products_for_sale_by_category_price

- Read Repair — таблица активно используется для чтения (поиск продуктов), позволит оперативно выявить и устранить расхождения.
- Anti-Entropy Repair — для восстановления после длительных сбоев
